# AGENTS.md — ThaaLam

Guidance for AI coding agents working on this repository.

## What this app is

ThaaLam is an offline metronome and tala practice companion for Android and iOS.
It uses the same stack as `../ukulele-companion`:

- `:shared` — Kotlin Multiplatform domain logic (no platform imports)
- `app` — Android, Jetpack Compose, MVVM + StateFlow
- `iosApp` — SwiftUI, generated by XcodeGen; links the KMP XCFramework

## Hard constraints

- **Offline only.** Do not add network permissions, HTTP clients, accounts,
  analytics, ads, crash reporting or telemetry.
- **No third-party audio SDKs without discussion.** The engines are built on
  `AudioTrack` and `AVAudioEngine` directly.
- **Timing is sacred.** Never schedule clicks from UI timers, coroutines,
  `Handler`, `Timer`, `DispatchSourceTimer` or display refresh. The click grid
  must be advanced by rendered audio frames inside the platform render path.
- **Accent edits must not restart the bar.** Main-beat kinds are resolved from
  the live settings snapshot at tick time.
- **Shared musical logic belongs in `:shared`.** If Android and iOS would
  otherwise duplicate a rule (meter grouping, tala angas, practice gating,
  preset format), put it in Kotlin and test it.
- **Do not call KMP in the iOS render callback.** Convert settings to plain Swift
  values on the main thread and use them inside `AVAudioSourceNode`.
- **Do not break accessibility.** Every beat needs a numeric/text label and a
  state description. Respect reduce motion.

## Build and verify

```bash
./gradlew :shared:jvmTest
./gradlew :app:assembleDebug
./gradlew :app:lintDebug
./gradlew :app:assembleRelease

cd iosApp
xcodegen generate
xcodebuild -project ThaaLam.xcodeproj -scheme ThaaLam \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

The iOS target runs the Gradle XCFramework task as a pre-build script. If you
edit shared Kotlin, the next Xcode build rebuilds the framework automatically.

## Where things live

- Pattern/timing math: `shared/.../domain/RhythmPattern.kt`, `TempoMath.kt`
- Layers/polyrhythm: `shared/.../domain/LayerCompiler.kt`, `VoicePattern.kt`,
  `data/LayerSettings.kt`
- Timing test contract: `shared/.../domain/TimingSimulator.kt`
- Practice logic: `shared/.../domain/PracticeLogic.kt`
- Tala data: `shared/.../domain/TalaLibrary.kt`, `data/Tala.kt`
- Swift-facing Kotlin API: `shared/.../domain/SwiftInterop.kt`
- Android engine: `app/.../audio/MetronomeAudioEngine.kt`, `ClickSynth.kt`
- Android app state: `app/.../audio/MetronomeController.kt`
- iOS engine: `iosApp/ThaaLam/Audio/MetronomeAudioEngine.swift`, `ClickSynth.swift`
- iOS app state: `iosApp/ThaaLam/ViewModels/MetronomeViewModel.swift`
- Architecture detail: `docs/architecture.md`

## Testing expectations

Add shared tests for any change to rhythm math, tala data, practice gating,
settings normalization or persistence. Run `:shared:jvmTest` and both builds
before declaring work complete. If you touch the iOS UI, verify at least the
metronome screen and the tala detail sheet on a simulator.

## Convention notes

- Android: Material 3, custom saffron/teal palette, 20 dp screen gutters,
  24 dp card radii.
- iOS: SwiftUI, dynamic `Color` helpers in `Theme.swift`, same visual language.
- User-facing copy is English for now; keep strings in resources where practical
  so localization is possible later.
- Presets/settings JSON is shared between platforms — do not rename fields
  without a migration or a new versioned key.
